## 요청 3건의 설계 (제안)

### A. 대화형(A/B) 화면 — Day14, 15, 16
원본 동작을 그대로 따르되, 원본처럼 코드를 복제하지 않고 **단계(step) 배열로 일반화**한다.
- 항목 정규화: 문장 항목은 단계 1개 `[{kr,en}]`, 대화 항목은 단계 2개 `[{role:A,kr,en}, {role:B,kr,en,context:A의 kr/en}]`. 각 단계는 "문제 → 정답 공개" 2국면. 대화 1세트 = 4국면(A 문제 → A 정답 → B 문제 → B 정답), 문장 1개 = 2국면. 같은 렌더/진행 로직 하나로 Day08과 Day14를 모두 처리한다.
- UI: 화살표 배지(A 질문 파랑 / B 답변 주황 / 문장 초록), 역할 원형 태그, B 차례에 A 대사를 보여주는 **맥락 박스**, 버튼 문구("A 정답 확인", "B 문제 풀기 →", "B 정답 확인", "다음 세트 →"), 직전 항목 표시 `Last: A: … / B: …`, 진행 표기 `Set n / N`(문장형은 `Step`), 카드 최소 높이 420px(대화/혼합 Day만)
- 타이밍: 문장 Day 생각 4.5s/확인 3.0s, 대화·혼합 Day 4.0s/2.5s (원본 값 그대로)
- 이전 버튼: 대화형은 원본처럼 국면을 한 칸씩 되돌리고, 첫 국면이면 이전 세트의 마지막 정답 화면으로 간다. 문장형은 현재 동작 유지
- 기존 기능과의 결합:
  - 사다리/랜덤/오답/홀수·짝수 필터는 **세트 단위**로 동작(원본도 세트 단위)
  - 영작 모드: A, B 각각 입력하고 채점. 오답 목록은 세트 단위 — 마지막 방문에서 채점한 단계 중 하나라도 틀리면 추가, 채점한 단계가 모두 맞으면 제거(빈 답안은 채점 제외)
  - 진행 저장: 이어하기는 해당 세트의 처음(A 문제)부터 시작
  - 홀수/짝수 필터는 `num`의 앞쪽 정수(그룹 번호)로 판단

### B. 총 문장 수는 실제 데이터 개수로 표시 — Day19
- 표시 문구는 `items.length`에서 계산하고, 원본의 "총 N문장" 표기는 사용하지 않는다 (Day19 → "총 66문장")
- 단위: 대화 항목이 하나라도 있으면 "세트", 아니면 "문장". 랜덤 모드 설명 문구와 "대상 N" 표기도 같은 값 사용
- 스크래핑 시 기록한 `declaredCount`는 참고 메타데이터로만 보존하고 불일치는 경고로 남긴다

### C. 문장 수가 4개가 아닌 Day를 정확히 반영
- 설정의 "누적 반복 단위"를 2가지 방식으로 바꾼다.
  - **그룹 단위(기본, 문장형 Day)**: 묶음 경계를 번호의 그룹 경계에 맞춘다. 그룹이 4·6·10개든 실제 크기만큼 정확히 누적한다. Day08은 그룹이 모두 4개이므로 **현재 사다리와 결과가 완전히 같다(320단계)**
  - **직접 설정**: 기존 슬라이더. 범위는 1 ~ max(8, 해당 Day의 최대 그룹 크기)로 Day에 맞춰 자동 확장 (Day19라면 1~10)
- 크기 1짜리 그룹이 연속되는 경우(Day09의 14~26번)는 최대 4개씩 한 묶음으로 합친다. 그러지 않으면 한 번 보고 지나가서 사다리 효과가 없다
- 대화·혼합 Day는 그룹이 5~12세트로 커서(그룹 단위로 하면 세트당 4국면이라 한 그룹이 수백 클릭) **기본을 "직접 설정 4"**로 두고, 사용자가 원하면 그룹 단위로 바꿀 수 있게 한다. 원본도 대화형 Day에는 고정 N만 있었다
- 기대 단계 수(검증용): Day08 320 / Day17·20 504 / Day19 582 / Day09 249

## 데이터 구조 (정규화)
스크래핑 원본(`data/dayNN.json`, `num/kr/en`, `a_kr…`, `isDialogue`)을 앱용 표준 형태로 변환한다. 원본은 `data/raw/`에 보존한다.
- 항목: `{ id, num, type: "sentence"|"dialogue", kr, en } | { id, num, type, a_kr, a_en, b_kr, b_en }`
- **ID = `{dayId}:{num}`** (예: `day08:1.(1)`, `day09:14`). Day09의 일반 숫자 번호 때문에 `num`을 쪼개지 않고 통째로 쓴다. Day 안에서 `num`이 유일해야 한다
- 그룹 번호 = `num`의 앞쪽 정수 (`14`→14, `3.(2)`→3). 번호 필터와 사다리 묶음에 사용
- `days.json`: `{version, days:[{day,id,title,format,count,file}]}`. `count`는 실제 개수, `title`은 `lessonTitle`

### (제외) 구글 시트 탭 구조 — 사용하지 않음
- `days` 탭: `day`, `title`, `topic` (드롭다운 표시용 주제, 예: "Day14 - 의문사 의문문(1)"). 현재는 `tools/normalize-days.js`의 `DAY_TOPICS`가 임시 출처
- `items` 탭: `day`, `num`, `type`, `kr`, `en`, `a_kr`, `a_en`, `b_kr`, `b_en` (사용하지 않는 칸은 비워 둠). 한 탭에 모든 Day를 넣는다
- 행 순서를 그대로 쓴다. 번호가 역행하면 경고

### Phase 3-1 — Day 선택 방식: 단일값 드롭다운 (Phase 3 UI 변경, Phase 4 전에 수행)
사용자 요청(2026-10-15): Study Day 선택을 **단일값 드롭다운 선택 방식**으로 바꿀 수 있게 한다.

**해석**: 드롭다운을 기본 선택 방식으로 제공하고, 기존 칩 방식은 코드 상수 하나로 전환할 수 있게 남긴다. 칩 16개는 모바일에서 여러 줄을 차지하므로 드롭다운이 기본값으로 적합하다.

**설계**
- 상수 `DAY_PICKER = 'dropdown' | 'chips'` (기본 'dropdown'). 설정 화면에서 값을 읽어 한 가지 UI만 그린다.
- 드롭다운: `<select id="day-select">` 단일값(value = dayId). 라벨 "Day 선택"은 `<label for>`로 연결해서 접근성 확보
  - 옵션 텍스트: `Day 03 · 예문 Drilling! (80문장)` — 문항 수와 단위는 Phase 3과 같은 데이터 기반 계산
  - 대화형 Day(14·15·16): `disabled` 옵션, 텍스트 뒤에 "(준비 중)" 표시
  - 현재 Day를 `selected`로 표시. 값은 `manifest`에서 생성
- 선택 시 동작은 칩과 같은 `selectDay(dayId)` 하나를 호출한다 (로딩 중 select 비활성화, 실패 시 이전 Day 값으로 되돌림)
- `?day=N`, 마지막 Day 기억(`delta:lastDay`), Day별 저장 분리는 두 방식 모두 그대로 동작

**구현 범위 (나중에)**
- `renderDayChips()`를 `renderDayPicker()`로 일반화: `DAY_PICKER` 값에 따라 select 또는 칩 렌더링
- 설정 화면 HTML: 칩 컨테이너(`#day-chips`)와 드롭다운(`#day-select`)을 모두 두고 `DAY_PICKER`에 맞춰 하나만 보이게 한다
- 제목·옵션 텍스트 갱신은 `applyDayUI()`에서 같이 처리한다
- 스타일: 드롭다운은 기존 입력 스타일(`rounded-2xl border-2 border-slate-100 font-bold text-slate-600`)을 따른다

**검증**
- 단일 값 확인: 드롭다운 선택 시 `#day-select`의 value가 한 개의 dayId이고, 대화형 옵션은 선택할 수 없다(disabled)
- 전환 확인: `DAY_PICKER`를 `chips`로 바꾸면 칩이 보이고 드롭다운은 숨겨진다 (두 모드 모두 Day 전환·?day=·Day별 저장 분리 통과)
- 기존 E2E `05-day-select.js`는 방식에 상관없이 Day를 고르는 헬퍼(`pickDay(page, n)`)를 통해 검사하도록 바꾼다. 두 모드에서 각각 실행한다
- 모바일 폭(390px)에서 드롭다운이 한 줄에 보이고 가로 스크롤이 없는지 확인

**열린 결정**: 기본값을 드롭다운으로 둘지 칩으로 둘지는 사용 후 바꿀 수 있도록 상수로 남긴다.
